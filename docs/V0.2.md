# Nectar v0.2 — the review-experience wave

*2026-07-19 · status: design, nothing built. v0.1 remains the already-promised cut-returns
(cli/backend modes, `[secrets]`, evidence verbs, portless adoption — V0.md's table). v0.2 is
the wave that makes the *taste itself* fast: land logged-in on the right screen, automate
the first look, and let previews leave the tailnet when explicitly asked. Contested choices
in DECISIONS D15–D20. Everything here surfaces to Apiary through the existing narrow
interfaces — `packet_fields`, `resolve`, evidence over :8440, the ax channel — and all
reviewer-facing UI (element picker, overlay, compare view) stays in Apiary (D20).*

Reserved error codes for this wave (join SPEC §7 as each feature lands, not before):
`E_SEED`, `E_DEPS`, `E_TASTE`, `E_EXPOSE`.

## 1. Scenarios — seeded, logged-in, deep-linked entry (D15)

The reviewer's first minute today: land on the app root, logged out, navigate by hand.
The design goal: **one click from the packet to the changed screen, authenticated.**

```toml
[scenarios.admin]
seed    = "pnpm seed:review --scenario admin"   # optional; publish-time, once per publish
entry   = "/admin/coupons"                       # deep-link path
login   = "node scripts/review-login.mjs admin"  # optional; prints a URL or path on stdout
default = true                                   # at most one scenario may be default
```

**Seed** runs during publish — after `[deps]` are up (§2), before the serve starts — in the
scrubbed environment plus the deps' injected vars and `NECTAR_SCENARIO=<name>`. Most seeds
are DB-level and need the database, not the app. A failing seed fails the publish
(`E_SEED`, log tail in the envelope) — the same stance as backend smoke (D12): a
half-seeded env wastes a reviewer's time with false signal.

**Login** is minted at **resolve time, never publish time** (D15). The command runs on the
publishing host, prints one line — an absolute URL or a path resolved against the
`is_self`-preferred base — and its output goes into the resolve result as `entry_url`.
Tokens are therefore short-lived and never stored in records, envelopes-at-publish, or
packets. The app-side convention: when `NECTAR_ENV` is set, the app enables a dev-only
token-login route (`/__nectar/login?token=…&next=<entry>`); a tiny middleware package
(Apiary-side, not this repo) makes that one line of setup for our stacks.

**Packet mapping.** `packet_fields` gains `review_entry_url` = base URL + `entry` — stable,
token-free, safe to sit on a packet for days. The desk calls `resolve` anyway and prefers
the fresh, authenticated `entry_url` when present; `nectar open` does the same (remote ref →
login minted via the existing ssh adapter). A human clicking the raw packet link lands
deep-linked but logged out — correct degradation.

Selection: `publish --scenario <name>` (seed choice), `resolve/open/taste --scenario <name>`
(login/entry choice); the `default = true` scenario applies when the flag is absent.

Failure modes: login command fails/times out (5 s) → resolve still succeeds with `entry_url:
null` and a `login_unavailable` warning — auth troubles must never make a preview
unresolvable. Seed failure → `E_SEED`, env kept `crashed` for inspection.

## 2. `[deps]` — per-preview resources (D16)

A generic way to declare what a preview needs spun up beside it: databases, caches,
buckets. The **primitive is a provision/teardown command pair**; docker kinds are sugar.

```toml
[deps.db]
kind = "postgres:16"          # sugar: container, volume, allocated port
env  = "DATABASE_URL"         # var injected into serve/seed/login/taste commands

[deps.cache]
kind = "redis:7"
env  = "REDIS_URL"

[deps.bucket]                                     # escape hatch — anything
provision = "node scripts/mk-preview-bucket.mjs"  # prints {"env":{"S3_URL":"…"}} on stdout
teardown  = "node scripts/rm-preview-bucket.mjs"

# or wholesale:
# [deps]
# compose = "docker-compose.preview.yml"           # docker compose -p nectar-<env> up -d
```

Semantics:

- **Per-env isolation.** Instances are named `nectar-<env>-<dep>` (compose project
  `nectar-<env>`), so two branches of the same app preview against separate databases.
- **Lifecycle bound to the env.** Publish provisions/starts; republish reuses data unless
  `--fresh`; `stop` stops containers; `rm`/gc-reap tears down containers *and volumes*
  (named, prefix-guarded `nectar-`, same stance as sim deletion). Expiry stops; cold tears
  down.
- **Env injection.** Each dep contributes vars to the scrubbed child environment of serve,
  seed, login, and taste commands. Order within publish: deps up → seed → serve → ready.
- Failure: `E_DEPS` fails the publish, teardown attempted, record `crashed` with log tail.
- Machine knobs: `deps_container_limit` (default 16); `doctor` checks docker/compose
  presence when any recipe on the machine declares deps.

Build order: compose + provision/teardown first (covers ~90% with nectar doing only naming,
lifecycle, env wiring, GC); `kind` sugar when patterns repeat.

## 3. `nectar taste` — the automated first look (D17)

```bash
nectar taste <env|ref> [--scenario s] [--routes /a,/b] [--against <env|branch>]
             [--video] [--json]
```

Playwright chromium, headless, an **optional dependency** — absent Playwright, `taste`
fails `E_TASTE` with the install hint; nothing else in nectar grows heavier. Per route
(from `[taste].routes`, plus the scenario's `entry`): authenticated visit (§1 login),
network-idle wait, screenshot; console errors, uncaught exceptions, and failed requests
collected throughout; `--video` records the session.

```toml
[taste]
routes   = ["/", "/admin/coupons"]
script   = "node taste.spec.mjs"        # optional; gets NECTAR_TASTE_URL etc.
fail_on  = ["console-error", "assertion"]  # what flips the taste to E_TASTE
max_diff = 0.02                          # with --against; DPC score threshold
```

Everything lands in the env's existing `evidence/` store — screenshots, `taste.json`
(per-route results), optional video — served over :8440 so the desk renders them in the
Test tab with zero new plumbing. The envelope returns evidence refs plus per-route
results. `nectar publish --taste` chains publish → taste so a bee's single command yields
surface + evidence.

**`--against`** publishes/reuses the baseline env (same app+mode, given branch — envs are
already per-branch), tastes the same routes/scenario on both, and shells out to **DPC**
(`NECTAR_DPC_BIN`, default `dpc`) per screenshot pair — never a JS pixel-diff dependency
(D17). Diff images + scores go to evidence; `max_diff` breaches count as failures when
`fail_on` includes `"diff"`. DPC absent → diffing skipped with a warning, taste otherwise
proceeds.

Side-by-side compare is a desk feature (two resolves, split view) — optional, never
compulsory, no nectar surface (D20).

## 4. `nectar drop` — small HTML artifacts (D18)

Publish a tiny static thing — an agent-written report, a dataviz, a mock — with none of an
env's machinery:

```bash
echo "<h1>coupons analysis</h1>" | nectar drop --name coupons-analysis --ttl 30d --json
# → { "drop_url": "https://<host>.ts.net:8440/drops/coupons-analysis-a1b2c3/", … }
```

- Input: a file, a directory (must contain `index.html`), or stdin (piped HTML).
- Storage: content-addressed under `packs/.drops/<name>-<shorthash>/`; **served by the
  existing :8440 pack server** — one small extension: a trailing-`/` request under
  `/drops/` serves that directory's `index.html` (still no listings, still no symlinks).
- Lifecycle: TTL (default 30 d) + LRU under the existing pack quota at gc. `nectar drops
  ls|rm` for management.
- Internet: `--to <target>` reuses §5's exposure targets (static copy, not tunnel — rsync
  to an xe.dev box / Cloudflare Pages). Tailnet-only ships first.

## 5. `nectar expose` — previews beyond the tailnet (D19, D21)

This deliberately amends SPEC §2's "Not public" non-goal: publishing stays tailnet-first
and nothing becomes reachable without an **explicit, per-env escalation**; `tailscale
funnel` remains forbidden.

**The first target is our own `nctr.site` relay (D21) — routing, not tunneling.** Every
publisher is already reachable on the mesh, so exposure needs no NAT traversal: one small
VM with a real public IP *joins the tailnet* and reverse-proxies `<sub>.nctr.site` to
the publisher's existing tailscale-serve URL. Publishing machines need **zero new daemons
and zero new credentials**. (Ruled by a three-model research panel, 2026-07-19:
docs/research/exposure-{codex,kimi,fable}.md — the panel wrote "nectar.site"; that name
was taken, the registered domain is **nctr.site**, on Cloudflare. Host: `trmd-vps01` —
public IP, tailnet member, Caddy already running.)

```bash
nectar expose <env> --to site [--gate password|none] [--password …] [--ttl 72h]
nectar unexpose <env>
nectar publish --expose site        # one-shot
```

The relay box (one-time bootstrap, ~half a day):

- **tailscale** with Tailscale SSH; the tailnet ACL grants it (plus operator devices)
  access to publishers' 8440–8542 — this is the §9.1 ACL rule gaining one member.
- **caddy** holding one wildcard cert for `*.nctr.site` via DNS-01 (requires the
  caddy-dns module build; the zone lives on Cloudflare free/gray-cloud and the DNS-edit
  token is the **only credential on the box**).
- **`nectar-relay`** — a small installed command, *not* a daemon: `add <sub> <upstream>
  <expires-at> [--password-hash H | --public]` writes a route file + `caddy reload`;
  `rm`, `ls`, `health`; hourly `prune` deletes past-expiry routes **even if the publisher
  is dead** — a vanished machine can never leak a public URL (belt: gc unexposes;
  braces: the relay prunes). Unrouted hosts get a branded "preview expired" page; dead
  upstreams a friendly "publisher offline" 502.

`nectar expose` drives it over Tailscale SSH — the same adapter remote refs already use.
Subdomains are `<app>-<branch-slug>-<eid>.nctr.site`; `--public` routes additionally get
an unguessable suffix. ios streams are interactive control surfaces (§9.1) and refuse
exposure without an explicit `--expose-interactive`.

Targets are machine config (infrastructure, not repo concern):

```jsonc
"exposures": {
  "site": { "kind": "relay", "host": "trmd-vps01", "domain": "nctr.site", "gate": "password" },
  "vercel": { "kind": "vercel-deploy" }
}
```

Later kinds, deliberately deferred: **ssh-tunnel** (sish) only for a publisher or relay
box that cannot join the tailnet; **exe-dev** (their `*.exe.xyz` proxy + login gate,
~zero credentials) as an internal-only nicety, never client-facing; **vercel-deploy**
(deploys the worktree rather than proxying — Vercel-shaped apps only) on demand.
**cloudflare-tunnel is likely never built**: Cloudflare Access/SSO and edge caching layer
*in front of* the relay by flipping the nctr.site DNS records to proxied — zero nectar
code (D21).

Rules: `--gate none` requires the explicit `--public` flag; the envelope gains
`urls.public` + `packet_fields.public_url` and a loud warning either way; gc unexposes at
expiry; `doctor` checks relay health (`nectar-relay health` over Tailscale SSH); failures
are `E_EXPOSE` and never affect the tailnet surface. The password gate is basic-auth in
the relay's route blocks — implemented once, centrally, and the designated D9 hardening
piece if the tailnet ever needs it too.

## Explicit non-features (ruled out this wave)

- **Review overlay / element-anchored feedback UI** — Apiary owns it; the desk already has
  an element picker. Nectar contributes references and evidence only (D20).
- **Taste receipts** (who-opened-when telemetry) — dropped as not important.
- **Compulsory compare** — compare is opt-in and desk-side.

## Sequencing

1. **Scenarios + auto-login + `review_entry_url`** — largest reviewer-time win; taste
   depends on it.
2. **`[deps]`** — real apps need a database before seeding means anything.
3. **`taste` v1** (routes, screenshots, console errors) → v1.1 (video, DPC `--against`).
4. **`drop`** (tailnet-only) — small, immediately useful, slots anywhere.
5. **`expose`** (nctr.site relay first — D21; ssh-tunnel/exe-dev/vercel later, on demand).

## Acceptance criteria

1. **Logged-in deep link.** A repo with `[scenarios.admin]`: `nectar publish --json` seeds;
   `resolve --json` on the desk machine returns `entry_url` that renders the target
   subpage *authenticated* in a fresh browser profile within 5 s. Packet's
   `review_entry_url` carries no token yet deep-links correctly.
2. **Login degradation.** Kill the login script: resolve still returns urls with the
   `login_unavailable` warning; nothing else breaks.
3. **Deps isolation.** Two branches of one app publish simultaneously; each sees its own
   postgres (distinct data proves it); `nectar rm --force` removes exactly its own
   containers+volumes; the other env keeps serving.
4. **Taste evidence.** `nectar publish --taste --json` on a repo with `[taste]` yields
   screenshots + `taste.json` in evidence, renderable via the :8440 URLs from the envelope;
   a planted console error flips the result to `E_TASTE` when `fail_on` says so.
5. **DPC diff.** `nectar taste --against main` produces per-route DPC scores and diff
   images; a deliberate visual change on one route breaches `max_diff` on exactly that
   route.
6. **Drop.** `echo … | nectar drop` returns a URL that renders from a second tailnet
   machine; gc removes it after TTL.
7. **Expose.** `nectar expose <env> --to site` yields `https://<sub>.nctr.site` that
   renders the env from a phone off the tailnet, behind the password gate; `unexpose`
   (and TTL expiry) kills it; the tailnet URL is untouched throughout; `tailscale funnel
   status` stays empty. Braces test: with the publisher disconnected from the tailnet,
   the relay's hourly prune still removes the expired route.
8. **A bee can do it.** One drone run: publish --taste with a scenario, put
   `review_entry_url` + evidence refs on a packet, human tastes logged-in from the desk —
   no human fixups.
