# Nectar v0 — the thinnest slice worth building

*2026-07-18. One machine-pair end-to-end: publish on A, taste on B. Everything else waits.*

## What's in

**Modes: `web` + the testpack convention (`desktop`).** Web is the highest-volume packet
kind and exercises the whole spine (worktree → serve → mesh URL → embed). The testpack is a
*convention* more than a system — the format and `pack`/`open` verbs — and shipping it in v0
means the desk's desktop Test tab has something real to point at from day one.

**Commands** (exact envelopes per SPEC §7):

- `nectar publish` — modes `web` and `desktop` only. Web: worktree, deps, `PORT`-injected
  serve, detached process, `tailscale serve --bg --https=<8443-8542>`, ready-poll,
  `packet_fields` in the envelope. Desktop: run recipe `pack`, validate + finalize
  `testpack.json`, zip into the pack store, emit `testpack_ref` (+ `preview_url` when the
  manifest embeds).
- `nectar ls` / `nectar show` — with lazy liveness (dead PID ⇒ `crashed` + log tail).
- `nectar open` — web: browser to `urls.mesh`; desktop: resolve ref → fetch over :8440 →
  sha256 verify → strip quarantine → launch `entry`. Cross-machine fetch is **in** v0 —
  it's the point.
- `nectar resolve` — the desk's one integration command.
- `nectar gc` — TTL expiry (stop process + remove serve entry), cold worktree deletion,
  pack-store LRU to quota, 6 h touch grace. Wired to an hourly pollinate schedule on each
  publishing machine.
- `nectar touch`, `nectar stop`, `nectar rm`, `nectar doctor` (check-only; `--fix` for the
  :8440 pack-store serve entry).

**Recipe**: `nectar.toml` parsing for `name`, `[web]` (serve/ready_path/ready_timeout/env —
literal values only), `[desktop]` (pack/kind/embed_url). Package.json `dev`-script fallback
for web.

**State**: file-per-env JSON records, atomic writes, the §4.2 directory layout.

**v0 rulings · 2026-07-18:** env identities and emitted refs are mode-qualified as
`<app>--<branch>--<mode>`; embedded desktop publishes own separate web and desktop records.
Whole-zip SHA-256 lives in the desktop env record and publish/resolve results, never inside
the self-containing manifest.

## Acceptance criteria

Setting: machine A = any agent host (e.g. `trmd-metal-1`), machine B = the reviewing Mac.
A real repo with a `dev` script (kontiki or apiary itself) and one Electron repo with a
`dist:testpack`-capable build.

1. **Web publish → remote taste.** On A, in a branch checkout: `nectar publish --json`
   exits 0 and returns `packet_fields.preview_url` of the form
   `https://<A>.tailca9707.ts.net:84xx`. On B, that URL renders the branch app in a browser
   within 5 s of the envelope returning. No flags, no config beyond `nectar.toml`/`dev`
   script.
2. **Idempotent republish.** Re-running publish on the same branch keeps the same URL and
   env name, picks up new commits, exits 0. A second branch of the same app gets a
   different port/URL; both serve simultaneously.
3. **Desktop pack → remote open.** On A: `nectar publish --mode desktop --json` emits a
   `nectar://` `testpack_ref`. On B: `nectar open <ref>` fetches, verifies sha256, and the
   app launches without any Gatekeeper "unidentified developer" block. Second `open` uses
   the local cache (no re-fetch).
4. **Embed mode.** For the Electron repo with `embed_url = "web"`: publish yields both
   `testpack_ref` and `preview_url`, and the `preview_url` renders the renderer in a plain
   browser tab on B.
5. **Envelope contract.** Every command with `--json` emits exactly
   `{ok, command, result|error}`; all failures in the F-table paths F1, F2, F4, F8 produce
   their specified behavior (F1/F2 verified by stopping portless/tailscaled; F4 by a
   recipe with a broken serve; F8 by corrupting a cached zip).
6. **Lifecycle.** `nectar ls` on A shows both envs with correct status and expiry. After
   `--ttl 1m` publish + 2 m + `nectar gc`: process gone, tailscale serve entry gone,
   `status: expired`, worktree still present; `nectar publish` revives on the same URL.
   An env touched by `nectar open` within the grace window survives `gc`.
7. **Crash honesty.** `kill -9` the dev server: `nectar ls` shows `crashed`;
   `nectar show` includes the log tail; republish restores the same URL.
8. **A bee can do it.** A hive bee on A, given only "publish this branch with nectar and
   put the fields on the packet," succeeds using `--json` output alone — measured by one
   real drone run, no human fixups.
9. **Doctor.** `nectar doctor` on a fresh machine reports the missing :8440 serve entry,
   `--fix` repairs it, and a 443 tailscale-serve entry (planted deliberately) is flagged
   as a portless conflict.
10. **Nothing public.** `tailscale funnel status` shows no nectar ports; all binds are
    loopback + tailnet serve entries only (spot-check with `lsof`).

Done means: criteria 1–10 pass, and one real review-desk packet has been tasted end-to-end
through a nectar reference (manual desk wiring is fine — `nectar resolve` + iframe).
