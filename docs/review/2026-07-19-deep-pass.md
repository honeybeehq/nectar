# Deep code pass — 2026-07-19

Full-codebase review of nectar v0 (src/ ~6.4k lines, test/ ~4.3k), run as three
parallel antagonist reviews (core lifecycle · modality/pack/security · CLI contract +
tests), findings verified against source, then fixed in place. Everything below is
**fixed and covered by the suite** unless listed under "Known remaining".
Baseline after the pass: typecheck ✓, lint ✓, 48 tests / 12 files ✓ (3 consecutive
stable runs; previously 2–3 files flaked per run).

## Flaky suite at HEAD (fixed first)

The suite failed nondeterministically on clean main. Two causes:

1. **Leaked fake AX-bridge processes.** The ios suite's fake bridge/helper never
   implemented the real bridge's die-with-the-app semantics, so every run orphaned a
   process that squatted on the 43xx test range (found 4300–4303 occupied by four
   previous runs). The fake now watches the app pid and exits.
2. **Collisions with real machine state.** The integration suite hardcoded pack-server
   port 4099 — the port the *real* nectar pack server on this machine legitimately
   occupies — and both suites allocated tailnet ports from the real 8443+ range.
   Every suite now gets fully disjoint upstream/tailnet/pack ranges (integration
   45xx/86xx, ios 43xx/87xx, cli 4099-default but sandboxed state), and assertions
   that raced the allocator (fixed `:4300` fetch, doctor's `:4099` log line) are now
   derived from the record/config instead. Test tempdirs are also cleaned up in an
   `afterAll` now — previously every run leaked `nectar-*` trees into tmpdir forever.

## High-severity fixes (concurrency/lifecycle)

- **Stale locks wedged envs forever.** The per-env lock was a bare O_EXCL file; a
  SIGKILLed publish left it behind and every later publish/gc failed "busy" until a
  human deleted it. Locks now record the holder pid and are stolen when the holder is
  dead. Busy is its own contract code, `E_BUSY` (was mislabeled `E_CHECKOUT`).
- **gc aborted wholesale on the first busy env** — the hourly sweep died mid-loop
  whenever any publish was in flight, violating SPEC's "safe to run concurrently".
  Each env transition is now isolated; busy/poisoned envs are reported in a
  `skipped` list and the sweep continues. Tested.
- **Port-allocation TOCTOU across concurrent publishes.** Two bees publishing
  different envs could both probe the same free port before either recorded a claim
  — worst case, one env's tailscale entry proxying the *other branch*. Allocation +
  spawn + record-write is now serialized under one machine-wide lock, and the
  reserved set additionally consults the live `tailscale serve` table (loopback
  probing says nothing about serve entries — F5 was probing the wrong thing).
- **Lock-bypassing mutations lost updates.** `touch`, `stop`, `rm`, and — worst —
  the touch-on-resolve writeback (which rewrote a *stale full record*) all mutated
  records without the lock. A desk resolve racing a republish could clobber the
  fresh `serve` block, permanently leaking the detached server. All mutations now go
  through a locked read-modify-write (`StateStore.updateEnv`); hot-path touches are
  best-effort (skip when a publish holds the lock — the env is obviously active).
- **Republish orphaned the old server on crash.** The record was overwritten
  (without the old `serve` pids) *before* the old runtime was stopped. Now stops old
  runtime first, while its pids are still on disk.

## Medium fixes

- **TTL rewrite on every resolve/open**: implicit touches reset expiry to the 72 h
  default, so a `--ttl 1m` env became a 3-day env on first desk render. Records now
  persist `ttl_ms`; implicit touches re-arm the env's own TTL. Tested.
- **F13 violated**: a crashed ios publish never deleted the nectar-created simulator
  device. It does now (`releaseSim` in the catch, prefix-guarded).
- **F12 degrade leaked**: the serve-sim process/serve entry survived `delete
  record.serve`, and the booted (RAM-heavy) simulator escaped the sim quota by
  design of the quota filter. Degrade now stops the stream process group, removes
  the serve entry, and shuts the simulator down.
- **Quota mode-confusion**: ios streams counted against the *web* quota; the web
  count also included silently-dead servers a bee could never free via gc. Now
  mode-filtered and liveness-refreshed.
- **Reap was incomplete**: gc's reap deleted worktree+record but left
  `packs/<env>`, `evidence/<env>`, `logs/<env>` forever; the specified evidence
  quota was entirely unenforced; killed publishes leaked `.staging-*` trees invisible
  to the zip-only quota walk. Reap now mirrors `rm`; gc prunes evidence per env to
  quota and sweeps stale staging dirs.
- **Machine-config write races**: `identity()` rewrote the config on every command,
  racing doctor's pack-server registration (lost pid ⇒ duplicate detached pack
  servers). Now writes only on change; gc re-reads before stamping `last_gc_at`.
- **finalizePack trash-then-rename** window left a serving env's resolve pointing at
  a 404; now a plain atomic rename-over.
- **pgid reuse**: stopping a long-dead record's process group could EPERM-throw (or
  escalate against a recycled pgid owned by someone else). EPERM now means "not
  ours — bail". (Full start-time verification deferred, see below.)

## Security/verification fixes

- **`nectar://` host injection** (MED): `parseRef` validated the env part but not
  the host, so a hostile ref like `nectar://-oProxyCommand/...` from a packet would
  smuggle an option-shaped argument into `tailscale ssh`. Hosts are now constrained
  to DNS-label form. Same class: branch names beginning with `-` are rejected before
  reaching git argv.
- **Symlinked testpack entry escaping the digest** (MED): extraction blocks symlink
  *writes* outside the root, but a symlink entry inside the pack could point outside
  it and pass the lexical containment check — `open` would launch/install a path not
  covered by the sha256. Entries are now realpath-contained; violations are
  `E_VERIFY`.
- **AX bridge readable by any web page** (MED): `/ax` (the full accessibility tree of
  the app under review) had `access-control-allow-origin: *` on loopback. Any page
  the operator visited could scan 41xx and read live UI contents. Now: Host-header
  check (kills DNS rebinding) and CORS is opt-in via `NECTAR_AX_ALLOW_ORIGIN`.
  **Apiary coordination**: if the desk reads `/ax` from a browser-origin context it
  must set that env (or read from the main process).
- **Unbounded in-memory testpack fetch** (LOW): `open` buffered the whole zip in RAM
  with no timeout; now streams to disk with a 10-minute abort.

## Contract fixes (the CLI *is* the product for bees)

- New contract codes `E_USAGE` / `E_BUSY` / `E_VERIFY` / `E_INTERNAL` (SPEC §7
  amended). Previously: every unexpected error surfaced as `E_CHECKOUT` (sending
  bees down F6 remediation for internal bugs), every argv mistake as `E_NO_MODE`,
  and sha-mismatch/manifest problems as `E_PLATFORM` (rendering as "wrong platform"
  for a corrupted download).
- Bare `nectar --json` returned `{"code":"E_NO_MODE","message":"(outputHelp)"}` —
  now a clean `E_USAGE` envelope; explicit `--help` stays human with exit 0.
- Remote errors no longer flatten to `E_NOT_FOUND`; the remote's semantic code
  passes through.
- `rm --force` was decorative; a serving env now refuses without it (`E_USAGE`).
- Recipe parsing is strict: typo'd keys (`ready_timout`) and the deferred
  `[secrets]`/`[cli]`/`[backend]` sections fail loudly instead of being silently
  ignored (an app running without its declared secrets was the exact failure class
  §9.2 exists to prevent). Deferred modes say "deferred to v0.1", not "not
  supported".
- `--ttl` is validated before any repo work.
- **New `test/cli-contract.test.ts`** drives the real built CLI: envelope shape,
  exit-code iff `ok:false`, `E_USAGE` mappings, bare-invocation behavior. `src/cli.ts`
  previously had zero test coverage and was excluded from the coverage config.
- New `test/ports.test.ts` covers the F5 allocator (skip-occupied, preferred-port
  reuse, reserved set, `E_PORTS` exhaustion) — previously untested logic.
- New state tests: stale-lock steal, `E_BUSY` on live contention, locked
  `updateEnv` + best-effort skip, corrupt-record tolerance in `listEnvs` (one
  truncated JSON no longer bricks ls/gc/publish).

## Known remaining (deliberate, ranked)

1. **No CI.** The repo has no git remote yet; when it gets one, add a macOS Actions
   workflow (`pnpm typecheck && lint && test`). House rule expects a green to rerun.
2. **Desktop/ios suites are darwin-arm64-only** (`currentPlatform()` throws
   elsewhere). Fine while v0 is darwin-only per spec; parametrize platform strings
   when linux/windows testpacks land.
3. **pgid start-time verification** — the EPERM guard is in; recording spawn time in
   the serve record and verifying before signaling would close the remaining
   theoretical recycled-pgid window.
4. **F6 borrowed-worktree behaviors and F11/F14 platform fast-fails have no tests.**
5. **`openIos` scratch simulator ignores the recipe's device/runtime** (hardcoded
   iPhone 17/latest) — resolve would need to carry those fields.
6. **Env identity vs serve recipe split**: the env name comes from the invoking
   checkout's recipe, the serve command from the branch's — a branch that renames
   `name` publishes under the stale name. Edge case; flagging, not fixing.
7. **Log tails can carry branch-printed secrets** — SPEC §9.2 now states this
   honestly; a scrubber for known secret shapes is the v0.1 option once `[secrets]`
   lands.
