# Shared static public exposure

Public static previews now work through relayd. Only an exact `/s/<env>/<32 lowercase hex token>/` prefix is accepted, in addition to origin-only dynamic upstreams. The caller must still own the MagicDNS hostname; ports are 8443–65535 excluding reserved 443/8440/8441/8450/8451. Queries, fragments, userinfo, arbitrary paths, encoded paths and traversal are refused. Prototype names and sanitized forms are refused. `src/relay.ts` already forwards the full mesh URL unchanged, so it needed no change. T1 already widened the relay port bounds; this work verifies them rather than duplicating that change. No publish capacity/eviction code changed.

The public URL stays at its existing root. Caddy prepends the exact prefix and strips it from the relative directory Location headers emitted by the shared server. Static public routes persist across relayd restart. Password gates and normal exposure lifetime stay intact.

Independent Claude Opus 5.5 review found request-side traversal after prefix rewrite. Real Caddy reproduced reaching a sibling static preview with a known token. The shared server now refuses raw dot segments, encoded separators and backslashes before WHATWG URL normalization; literal, encoded, mixed-case and backslash real-Caddy attacks return 400. The reviewer rechecked the fix and reported no blocking flags. Remaining minor points: malformed upstream path errors use the generic upstream_host rule, and redirect stripping handles relative Locations (the current server contract).

## Rollout

Upgrade the production nectar-relayd binary before exposing shared static previews. The normal relayd startup rerenders existing route files and reloads Caddy; keep the Caddy route-directory import and configured reload mechanism. Deploy the publisher/shared-server build too, including the raw-path guard. Keep the relay's stable-node allowlist and ungated allowlist unchanged. Its network policy must permit the relay to reach publisher preview ports 8443–65535 (including the singleton static port); no policy or production relay was changed here.

Rollback requires care: old relayd considers static upstreams invalid and refuses to start on the whole persisted state file. Remove static public routes using the upgraded relay's supported admin API/CLI before downgrading. Existing origin routes can remain. Do not edit live state manually.
