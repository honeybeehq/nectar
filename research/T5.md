# T5 — recover capacity without retiring previews

Dynamic publish and wake handle E_QUOTA and upstream E_PORTS by sleeping the running,
dynamic app with the oldest real view. Live proxy activity supplements the
persisted timestamp; unknown activity is protected. Pin/keep, main bench, active HTTP
responses, streams/upgrades and static previews are excluded. Recheck under the env
lock, gate requests arriving during sleep, preserve files and URL routes, and retry
until admission succeeds or no eligible runtime remains. Tailnet exhaustion skips
sleeping because retained URL routes cannot be reclaimed this way.

After local recovery, ordinary publish can try configured pool hosts with the existing
least-loaded/dependency/mesh-denied chooser and retry capacity refusals. No configured
pool means an actionable error: add a host with `nectar pool add <host>`, free memory or
widen custom ranges. Decision: do not auto-discover unconfigured hosts. Tailnet access
does not authorize code shipment. Explicit --local/--host and received shipments do
not bounce through pools.

Wake placement ships the exact recorded commit, persists the remote HTTPS target
under the source env lock, and proxies HTTP/upgrades through the original URL.
Remote copies have the remaining original TTL. This code is implemented but NOT
exercised across hosts: SSH as trmd was denied on trmd-metal-1, trmd-metal-3, netcup-1
and netcup-2. No other agents' daemons or previews were used. Remaining limitation:
a dead remote target requires republish; local removal does not immediately stop the
remote copy. Cold wakes retain per-env concurrency; admissions may reclaim extra
runtimes concurrently rather than blocking every preview behind a slow app start.

## What T6 must say

- `result.preview_url` is directly usable in proof and equals
  `result.packet_fields.preview_url`. This top-level field is new; the existing nested
  field remains. Existing remote daemons' nested field is normalized on return.
- `result.slept_previews` lists names put to sleep during the publish (empty otherwise).
  Sleeping keeps the URL and wakes on a visit; it is not deletion or retirement.
- Capacity placement adds `placed_on` and `placement_reason`, and returns the final
  destination URL. Existing configured default/sticky placement remains intact.
- Wake recovery exposes slept names in `x-nectar-slept-previews`; daemon state has
  `capacity.jsonl` events with slept names or the placement host and remote URL.
- Dynamic publishes with nectard usually prepare a sleeping URL without memory
  admission; pressure is handled on the visit. Static previews do not use runtime
  memory admission or per-env ports and are never capacity victims.
- Finite custom ranges can still exhaust: URL listeners cannot be removed merely to
  make room. No pool configured yields an actionable capacity message, never a count
  of preview slots.

## Real verification

Reproduce: `pnpm build && node test/fixtures/verify-recovery.mjs`.
Private NECTAR_HOME and private control socket, real nectard, real git fixture,
real publishes through the control API and HTTPS curl of the returned URLs.
The explicit fixture-only NECTAR_TEST_RUNTIME_MEMORY_BYTES budget is 12 × 256 MiB;
this exercises synthetic admission, not actual host RAM exhaustion/MemAvailable.

The first twelve previews publish and wake. Every wake must preserve the exact issued
mesh URL. With a 24-port app range, publish 13 sleeps p03 and names it in the envelope;
p01 is pinned and p02 holds an open stream. Widen app bounds, wake p13, then visit
slept p03: memory admission sleeps p04, response is HTTP 200, and its header names p04.
With all remaining previews pinned, p14 reports the actionable no-pool E_PORTS error.
Cleanup asserts no own routes remain and all 14 observed app PIDs are gone.

An integration bug uncovered during reruns is fixed: T1's all-interface probing sees
Nectar's own existing Tailscale listener. Probing that retained port during T3 wake
used to move the URL and leak the old route. Confirmed owned routes are now reused
without probing their own listener. Earlier failed runs were superseded; their own
stale entries were removed with Nectar's stopServe helper after matching recorded
fixture proxy targets. No foreign route was changed.

Typecheck/build/lint pass. The full suite and unchanged baseline each have 358 passed,
8 failed, 3 skipped, with identical failure names (existing Linux/platform/GC fixtures).
No new unit tests were added. No repository verification skill exists. No UI changed;
screenshots and a lasting live UI preview are not applicable. Fixture URLs are stopped
after the run to avoid consuming capacity.

Cross-model review: claude-opus-5-5. Lock stalls, non-progress retries, route preservation
and post-shipment persistence were corrected. Remaining attention: unexercised remote
placement and its dead-target/teardown limits; synthetic memory admission; concurrent
recovery can put more apps to sleep than a serialized admission would.
