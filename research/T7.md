## Integration fixes

1. ProxyHub previously queued already-read snapshots. A stale snapshot could close a newer preview listener immediately after successful publish: first run returned HTTPS 502 and daemon log showed proxy open/close/open. Serialized sync now reads current records when it executes, while retaining supplied records for existing test doubles.
2. `stop` did not turn `warm` dynamic records into `stopped`. The daemon could recreate the sleeping listener after explicit stop. Stop now transitions warm web records to stopped. The first cleanup exposed a retained own route; it was later removed using Nectar stop against that fixture only.
3. Shared static checked wall-clock TTL before proof protection. GC kept waiting/unknown previews, but their URLs returned 410. Expired-timestamp requests now consult the existing proof adapter: only confirmed unlinked previews expire before GC; terminal retirement remains GC's responsibility after grace. Explicit expired/cold/stopped state still refuses serving. The singleton receives the configured adapter executable explicitly through its scrubbed environment. Adapter wrappers must set their own credential/config environment as documented in T8.

The third fix deliberately makes unresolved proof lookup conservative, matching T4. It invokes lookup only after TTL, with the existing 10-second timeout and no cache. This can add latency after expiry; it preserves waiting proofs over availability of the lookup service.

## Limits and checks

Memory pressure uses the existing fixture-only `NECTAR_TEST_RUNTIME_MEMORY_BYTES` seam, not physical host exhaustion. Lazy publish itself needs no app memory: memory recovery is proved on the first visit; a separate finite-port publish proves the named publish recovery path. No remote placement, public relay, production Apiary credentials, macOS runtime or fleet rollout is claimed. T10 independently verifies public relay. These fixtures exercise the T4 adapter contract, not Apiary's matching implementation.

The full Linux suite uses a private network namespace and two workers, avoiding foreign fixed-port collisions. The recorded known baseline is eight failures, 358 passes, three skips; final changed-vs-archived-base results are recorded in the accompanying suite logs. Typecheck, lint and build logs accompany the run. Full suite is not claimed green.

Earlier runs are diagnostic, not the passing result. First run shows proxy 502; second stopped at unsupported control `gc` and cleanup exposed warm-stop routing; corrected fixture calls real `service.gc()` against its own home. Third passed before adding explicit unlinked expiry and named publish checks; canonical final run includes both. No browser screenshot/recording tooling was used; real curl HTTPS cold-wake timings are the primary evidence. No UI changed and fixture URLs were intentionally stopped after verification, so there is no lasting UI preview.
