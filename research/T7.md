## Integration fixes

1. ProxyHub previously queued already-read snapshots. A stale snapshot could close a newer preview listener immediately after successful publish: first run returned HTTPS 502 and daemon log showed proxy open/close/open. Serialized sync now reads current records when it executes, while retaining supplied records for existing test doubles.
2. `stop` did not turn `warm` dynamic records into `stopped`. The daemon could recreate the sleeping listener after explicit stop. Stop now transitions warm web records to stopped. The first cleanup exposed a retained own route; it was later removed using Nectar stop against that fixture only.
3. Shared static checked wall-clock TTL before proof protection. GC kept waiting/unknown previews, but their URLs returned 410. Expired-timestamp requests now consult the existing proof adapter: only confirmed unlinked previews expire before GC; terminal retirement remains GC's responsibility after grace. Explicit expired/cold/stopped state still refuses serving. The singleton receives the configured adapter executable explicitly through its scrubbed environment. Adapter wrappers must set their own credential/config environment as documented in T8.

The third fix deliberately makes unresolved proof lookup conservative, matching T4. It invokes lookup only after TTL, with the existing 10-second timeout and no cache. This can add latency after expiry; it preserves waiting proofs over availability of the lookup service.

4. Recipe-backed static-server commands incorrectly entered T3's lazy dynamic registration before T2's singleton branch. A shared `isStaticServe` predicate now routes those recipes through static startup. Legacy records that already have a per-preview serve remain eager to retain their old URL/process model. The existing static-command substring heuristic remains a known limitation: a custom command containing `static-server.` can be mistaken for the bundled server.

## Limits and checks

Memory pressure uses the existing fixture-only `NECTAR_TEST_RUNTIME_MEMORY_BYTES` seam, not physical host exhaustion. Lazy publish itself needs no app memory: memory recovery is proved on the first visit; a separate finite-port publish proves the named publish recovery path. No remote placement, public relay, production Apiary credentials, macOS runtime or fleet rollout is claimed. T10 independently verifies public relay. These fixtures exercise the T4 adapter contract, not Apiary's matching implementation.

The full Linux suite uses a private network namespace and two workers, avoiding foreign fixed-port collisions. The recorded known baseline is eight failures, 358 passes, three skips; both archived unchanged d5eeb86 and final changed source produced exactly 358 passed, eight failed, three skipped, with identical failing names (docs/evidence/T7-checks.txt; final source log docs/evidence/T7-suite-last.log). Typecheck, lint and build logs accompany the run. Full suite is not claimed green.

Earlier runs are diagnostic, not the passing result. First run shows proxy 502; second stopped at unsupported control `gc` and cleanup exposed warm-stop routing; corrected fixture calls real `service.gc()` against its own home. Third passed before adding explicit unlinked expiry and named publish checks; canonical final run includes both. No browser screenshot/recording tooling was used; real curl HTTPS cold-wake timings are the primary evidence. No UI changed and fixture URLs were intentionally stopped after verification, so there is no lasting UI preview.

Baseline expiry reproduction: the existing proof-gc fixture in the source archive needed its obsolete post-reap fetch-reject assertion adapted to HTTP 404 (shared server remains alive). It then reproduced the waiting-preview expiry body instead of its expected content. See docs/evidence/T7-expiry-repro.log. Production source in that archive remained unchanged.

## Review follow-up and policy decision

Expired static URLs on hosts **without a configured proof adapter now continue serving until an adapter is installed and confirms them unlinked or terminal GC retires them**. GC already preserved those records under T4. This closes the URL-level bypass, but changes T2's no-adapter wall-clock expiry behavior. It is explicitly flagged in the proof's needsJudgement for approval. The final run removes the adapter, restarts the singleton, expires a fixture, then proves HTTP 200 and GC's not-configured skip. Adapter changes require a singleton restart because its environment is captured at spawn.

Expired requests share one in-flight lookup per preview without caching decisions. Each lookup retains the existing 10-second timeout. This bounds duplicate concurrent asset lookups per preview; many distinct expired previews can still invoke adapters concurrently. No fleet-scale lookup/load guarantee is claimed.

The initial measurement overlapped suites/builds and is superseded by the final 15:30:03–15:30:57Z combined run, which ran after build and both older fixtures, with no concurrent suite/build. The final fixture records statusBefore, so cold timings use actual warm state rather than a latency threshold. Its raw field `publishNamedLeastRecent` is an old label for the returned port-pressure victim; that check proves named recovery and victim wake, **not LRU order under port pressure**. The script now names the field publishNamedVictim. A diagnostic expected p03 but got p06; the final run selected p05. Code can skip busy/locked candidates, but the logs do not prove which candidates were skipped or why. Only the first synthetic-memory victim, p01, is verified as least recently viewed. The next wake selected p10 rather than p02; the logs do not explain this. General ordering under memory or port pressure is unverified and needs follow-up on runtime activity/record-lock eligibility.

The old shared-static fixture now explicitly supplies an unlinked adapter, waits for daemon proxy assignment after manually injecting a legacy record, checks the canonical mesh URL, and curls the returned local proxy URL. Its bounded E_BUSY retries log every attempt. Final old-fixture run required zero retries. Unchanged base reproduced an E_BUSY stop and failed the recipe-singleton assertion. An earlier changed diagnostic hit E_BUSY during legacy republish, then moved the URL on retry: the accepted T3 contract explicitly allows a failed publish to release its route and a retry to receive a different URL. Successful republish URL stability is proved by the final run. No broader failed-publish transaction guarantee is added.

Old proof-gc required fetch rejection→HTTP 404 adaptation because the shared server remains alive after one route is reaped. Its final run passes clock reset, unknown retention, dry-run, landed retirement and waiting/failure URL checks. Both fixture singletons are explicitly stopped after daemon exit.
